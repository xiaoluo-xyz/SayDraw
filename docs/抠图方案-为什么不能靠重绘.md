# 抠图为什么老是做不对 —— 复盘与修复

日期:2026-10-21 · 触发:会话「把图中的键盘抠出来」的完整操作记录

## 1. 那次到底发生了什么

用户上传一张白色键盘的实拍照片,只说了一句「把图中的键盘抠出来」。操作记录(导出自会话数据):

| 时间 | 动作 | 结果 |
|---|---|---|
| 17:39 | 模型判断"没有抠图工具",选择用 `generate_image` 重画一张白底版 | 3 张候选(¥1.05,290 秒)。**键帽形状、键位数量、小狗铭牌都变了** |
| 19:08 | 用户:"那个徽标不是键帽,你自己先放大仔细看一下所有的细节" | 模型用 `composite_image` **裁剪**放大看了 4 个区域(¥0,正确用法) |
| 19:09 | 模型承认"重绘式抠图保不住细节",但仍选择"再重出一批" | 又 3 张(¥1.05,196 秒),其中 2 张直接把竖置键盘画成横的 |
| 19:27 | 用户停止 | 总耗时 19 分 45 秒,7 张图,¥2.10,交付物为 0 |

同时暴露的 4 个产品缺陷:

1. **把"抠图"当成"重绘"**:抠图要求像素保真,而生图模型只能重画,这条路注定失败却花了 6 张图才发现。
2. **没有本地抠图能力**:应用当时只有贴图/调色/裁剪/圆角/拼接,遇到"去背景"只能绕回模型。
3. **分析用的裁剪图进了版本树**:4 张只为放大看细节的裁剪图变成「改版1…改版4」,还占了版本链。
4. **失败的重试被确认门拦住 + 尺寸超限**:另一次验收里,`edit_image` 传 3072×4096 被端点拒绝(长边上限 3840),这次**失败**却已经消耗了"本轮已生成"的额度,下一次调用被要求"先征得用户同意",把用户拉进来点确认。

## 2. 试过的三种自动抠图算法(都在真实键盘照片上验证)

| 方案 | 做法 | 结果 |
|---|---|---|
| 全局背景色板(k-means 采样边框) | 按颜色聚类判断前景/背景 | **失败**。白色键盘的暗部与深灰垫子的高光同色,键帽被整片当成背景吃掉,只剩 5.5% 前景 |
| 逐像素色差区域生长 | 从四边泛洪,相邻像素差 ≤ 容差就吞掉 | **部分成功**:键盘整体出来了,但键盘外壳被"吃掉"(壳体色与垫子过渡太平缓),还残留一块投影 |
| **梯度墙 + 区域生长** | 先用 Sobel 求强边缘当"墙",泛洪既不穿墙也不跨颜色突变 | **成功**。投影是软的(梯度低)→ 被吃掉;键盘轮廓是硬的(梯度高)→ 挡住。3072×4096 实测 1.4 秒,前景 35.1%,白底/透明底都可用 |

最终算法(`src/shared/composite.ts` 的 `autoCutout`):

1. 缩到长边 ≤1600 算蒙版(省内存、抗噪),再双线性放大 alpha 回到原分辨率;
2. 灰度 → 3×3 平滑 → Sobel 梯度;阈值取梯度分位数(默认 0.9)并保底 8(纯色图不会有墙);
3. 从四边泛洪:不穿墙、且相邻像素 RGB 差 ≤ 容差(默认 30);
4. 前景 = 没被泛洪到的像素 → 只保留最大连通块 → 向"未泛洪"方向膨胀 2px,把主体轮廓上的墙像素补回来;
5. 填洞(键帽缝隙、壳体内部重新变实心)+ 羽化;可选铺底色(`background`)与自动裁紧(`trim`,裁切框按 alpha 算,不受铺底影响)。

## 3. 保底方案:模型只出剪影,像素仍来自原图

`cutout` 支持 `maskAssetId`:让 `edit_image` 只生成一张**黑白剪影蒙版**(白=主体、黑=背景、不要内部细节),再 `cutoutWithMask` 把**原图**像素切下来。模型只回答"哪儿是主体",不碰像素,所以键帽/铭牌/文字不会变。

实测两个注意点(已写进提示词与工具说明):

- 蒙版**尺寸不必与原图一致**(内部会缩放对齐),别为了对齐去传 4K 尺寸;
- 蒙版极性默认「白=保留」,反了就传 `invertMask:true`;工具会在"前景 <1%"(几乎全删)或 ">98.5%"(几乎没删)时直接报错并提示怎么办;
- 这类模型**不一定尊重原图构图**(实测它把竖置键盘画成了一块横向圆角矩形),所以它是保底方案,首选仍是本地自动抠图。

## 4. 顺带修掉的问题

| 问题 | 修法 |
|---|---|
| 分析用裁剪图进版本树 | `composite_image` 新增 `inspect:true` → 产物 `kind='annotation'`,不进版本树、不出现在成果图里,上下文里标注为「分析用局部放大图」 |
| 失败的生图/编辑也消耗"本轮已生成"额度,导致重试被确认门拦住 | 只有**真的产出图片**(`ok && assetIds.length>0`)才推进迭代门;端点拒参、尺寸非法这类失败不再拉用户点确认 |
| 端点拒绝超大尺寸(长边 >3840) | 新增 `clampImageSize`:请求前按比例收敛(边长取 8 的倍数),并如实回报「原请求 X 被收敛为 Y」 |
| 同一目标无限重出候选 | 系统提示新增硬规则:同一需求最多两批(每批 ≤3 张),两批不达标必须停下来给本地方案或让用户取舍 |
| 抠图被当成重绘 | 系统提示新增两节:「抠图必须"算"不能"画"」「内部分析图不进版本树」,并明确"不要把重绘抠图说成像素一致" |

## 6. 已知边界

- 主体与背景**都有强边缘且互相贴合**时(例如白纸上的白杯子),梯度墙会把两者一起圈进前景,表现为"背景没去干净"。此时调低 `edgePercent`(如 0.8)让它更激进,或走蒙版方案。
- 轮廓外侧可能留一圈很淡的环境色描边(那是原图边缘像素本身,不是重绘产生)。要更准的边缘控制就用蒙版路线:蒙版决定边界,原图决定像素。
- 头发、毛绒、半透明边缘需要 alpha matting,本地只做羽化过渡,做不到丝状逐像素;这类素材建议提供更干净的背景照或蒙版。
- 抠图不改变光影:抠出来的主体仍带原环境光,要重新打光需再用 `edit_image`(那一步是重绘,需用户确认)。
