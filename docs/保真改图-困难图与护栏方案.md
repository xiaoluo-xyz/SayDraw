# 保真改图:困难图清单、可行性分析与「只改该改的」护栏

> 2026-10-22。对应需求:改图不能只把要改的地方改掉,还必须保证**不该改的地方一个像素都没动**;而且一张图被反复修改后,要和**最初上传的素材**比对,而不是和上一版比对。

## 0. 结论先说

1. **"事后比对"必要,但单独用不够。** 比对只能*发现*漂移,不能把已经画坏的像素还原;重跑一次是重新抽卡,不保证更接近原图。
2. 真正能"防止改坏别处"的是**合成约束**:把模型输出只当"允许区域内的补丁",区域外逐像素取原图。这样"区域外 0 改动"是**构造出来的**,不是检查出来的。
3. 纯换色(把键帽改成主体色、把背景改白)**根本不该交给生图模型**:用确定性逐像素换色 `paint`,几何形状不可能变,徽标不会被当成键帽重画。
4. 你提的"跟原图比对"已经落地为三条:版本链根 `originAssetId`、允许区域 `protect/compareregion`、差异热图 + 边界锚定率。实测里模型确实会顺手改掉 9%~14% 的其它区域,护栏把这些全部还原成原图像素。

说明:这些类型不是凭感觉列的。指令编辑 benchmark(GEdit-Bench、ImgEdit、MIRAGE 等)本身就把"文字、身份保持、局部编辑、多实例"单列成难点;图像编辑论文也普遍把"未编辑区域保持一致"当核心指标。

| # | 类型 | 难在哪 | 典型指令 | 模型常见的坏法 |
|---|---|---|---|---|
| 1 | 密集小字 / 标签 / 书脊 | 文字是离散符号,重绘时按"看起来像"生成 | "把序列号改成…" | 旁边几行字被重排、字重变、数字糊 |
| 2 | 重复规则结构(键盘、表盘刻度、电路、格纹) | 相位/间距必须逐项对齐,模型没有"这是 87 个键"的概念 | "把键帽换成黑色" | 键位数量/间距变、整排错位、个别键旋转 |

| 7 | 透明 / 反光(玻璃瓶、镜面) | 折射与反射要物理一致 | "把背景换成蓝色" | 反射被抹平、瓶身变形 |
| 8 | 精确颜色 / 材质 | 目标色号、木纹→大理石要保留纹理 | "背景改成 #1E90FF" | 色偏、渐变带、纹理被重画 |

## 2. 你的建议:可行,但可以更进一步

> "再次修改要对原本上传的素材主体进行比对,避免修改 A 点还把 B 点一块改了。"

**可行性:高。** 只要版本链里保留"根资产"(第一次上传/生成的那张),任何时候都能拿当前图和它逐像素比。我们把这件事做成三件套:

1. **版本链根**:每个资产记录 `originAssetId`;编辑默认以根为基线,不受中间版本累积漂移影响。
2. **允许区域**:比对必须知道"哪块是允许改的",否则整图 diff 只能告诉你"变了 12%",不能判断该不该变。
3. **两个指标 + 一张图**:
   - `区域外改动比例`:不该动的地方动了多少(硬指标);
   - `边界锚定率`:区域内"模型新画出来的边界"有多少能在原图 ±2px 内找到依托(重绘/位移的代理指标);
   - **差异热图**:红=允许区域内改动,黄=区域外改动,给人和模型看。

**但只靠"比对"有两个绕不过去的坑:**

- 事后比对只能判"变了",不能判"变坏了",更不能把改坏的像素变回去。发现不合格 → 只能重跑(重新抽卡)。实测模型一次就改掉 9%~14% 的其它区域,重跑同样可能。
- 边界锚定率对"文字替换"天然偏低(新字必然产生新边界),对"密集重复结构"又不够敏感(键位平移后仍能找到相似边界)。它是参考值,不是判决书。

所以更好的方案是**三层**,比对只占最后一层:

| 层 | 做什么 | 保证 |
|---|---|---|
| ① 不生成 | 纯换色/改明暗/贴回原件 → `paint` / `composite_image` 确定性像素操作 | 几何 100% 不变(没被改的像素逐字节相同) |
| ② 限制生成 | 必须模型重绘时,`edit_image.protect` 只把结果当"区域内的补丁"贴回原图 | 区域外逐像素 = 原图(构造保证) |
| ③ 改完对账 | `compare_image` + 差异热图 + 边界锚定,交付前自检 | 用数字说清"改了什么、没改什么" |

一句话:**能"算"的别"画";必须"画"的只让它画一块;画完拿原图对账。**

## 3. 实现

### 3.1 确定性换色 `composite_image.paint`

```jsonc
{
  "assetId": "asset-xxx",
  "paint": {
    "targetFrom": { "x": 0.5, "y": 0.12 },  // 从键盘壳体取样(目标色)
    "color": "#e9e6dd",                     // 只选接近这个颜色的像素(白色键帽)
    "tolerance": 30,
    "region": { "x": 0.1, "y": 0.15, "w": 0.82, "h": 0.6 }, // 可选:限定区域
    "exclude": [{ "x": 0.9, "y": 0.68, "w": 0.08, "h": 0.12 }], // 可选:徽标不参与
    "preserveShading": true
  }
}
```

- 选区来源:蒙版(白=可改)/ 矩形 / 颜色相似度;三者可叠加。
- 目标色:色号或从图里取样(`targetFrom`)。
- `mode`:`albedo`(工具默认)= 线性光下估计白色物体的白点,把**漫反射反照率**换成目标色,阴影/边缘/高光仍由原光照决定;`shade` = 旧行为(按原明暗比例染色,深色时容易像盖涂层)。
- `highlightProtect`(0-1,默认 0=哑光):albedo 模式下额外保留镜面高光的强度;亮面/金属再调高。
- `shadowLift`(0-1,默认 0):哑光暗部太死时加一点目标色环境光。
- `preserveShading` 为 false 时退化为纯色平涂。
- **只有 `weight>0` 的像素被改写**,其余像素逐字节不动。工具返回 `painted` 像素数、`coverage`、与目标色的 `meanDelta`、`highlightRetention`。
- `maskGrow`(0-16px):蒙版只盖到键帽顶面时,把选区向外扩,连键帽侧壁一起刷;`coverage`/`painted` 只统计权重 ≥5% 的"看得出来"的改写,避免抗锯齿边缘把 33% 虚报成 73%。

### 3.2 模型重绘护栏 `edit_image.protect`

```jsonc
{
  "assetIds": ["asset-xxx"],
  "instruction": "把 S/N 改成 2025-01-0042-A",
  "protect": {
    "region": { "x": 0.02, "y": 0.245, "w": 0.46, "h": 0.075 },
    "featherPx": 2,
    "minAnchor": 0.72
  }
}
```

流程:

1. 解析允许区域(矩形或蒙版);没给区域直接报错(避免"看起来保护了"其实整图放行)。
2. 基线 = `baselineAssetId` 或**版本链根**(用户最初上传的那张)。
3. 调模型,拿回编辑图;按基线尺寸缩放对齐。
4. 合成:`out = 基线 × (1-a) + 模型结果 × a`,其中 `a` 是允许区域(羽化只向内,矩形外强制 0)。
5. 输出报告:`regionOut`(合成前模型在区域外改了多少)、`deliveredOutside`(交付图区域外改动,构造上为 0)、`insideChangedRatio`、`edgeAnchor`、`newEdgeRatio`、区域外改动聚集块。
6. 存资产时写 `meta.guard` 与 `meta.originAssetId`;结果文本直接告诉模型这些数字。

#### 3.2.1 自动护栏 `protect.auto`(不给选区也能护)

```jsonc
{
  "assetIds": ["asset-xxx"],
  "instruction": "把白色键帽改成黑色塑料键帽,外壳/徽标/屏幕不动",
  "protect": { "auto": true }
}
```

- 既没给 `region` 也没给 `maskAssetId` 时,护栏先算"模型改了哪里",按 8 邻域做连通块切分:
  - 面积 ≥ `minIslandShare`(默认 0.04% 全图)的块 → 判为**成片改动**(换色/换材质),保留;
  - 其余 1–2px 的孤立块(桌面纹理抖动、压缩噪点)→ 还原成原图像素。
- 保留区再外扩 `growShare`(默认 0.8% 图宽)并羽化,把改动的软边一起留下。
- 报告里多出 `autoGuard: { islands, kept, keptCoverage, revertedShare }`,note 直接写"把改动切成 N 块,留下 M 块成片改动(占 X%)"。
- 代价:同一块里的东西会被一起放行 —— 徽标/屏幕若和要改的物体连成一片就保护不到,这种必须改用 `region`/`maskAssetId`。auto 模式下的"区域外 0%"是构造出来的,真正有信息量的是 `revertedShare`(还原了多少)和 `kept`(留了几片)。

### 3.3 交付前对账 `compare_image`

```jsonc
{ "assetId": "asset-new", "baselineAssetId": "asset-root", "region": {…}, "heatmap": true }
```

- 不给 `baselineAssetId` 时自动沿 `parentId` 找根。
- 输出:允许区域占比、区域内改动、区域外改动(及最多 3 个聚集块的归一化位置)、边界锚定率、新边界占比、热图(标注图,不进版本树)。
- 判定:`区域外 >1%` 或 `最大聚集块 >0.3%` 或 `锚定 <0.72` → 「保真可疑」,并给建议(用 protect 重跑 / 纯换色改 paint)。

### 3.4 顺手修掉的端点约束(测试中发现)

- 宽高必须是 **16 的倍数**(`1000×640` 被拒:Width and height must both be divisible by 16)。
- 像素量不能太小(`1008×640` 被拒:below the current minimum pixel budget)。
- `clampImageSize` 现在统一收敛:长边 ≤3840、宽高为 16 的倍数、像素量 ≥1MP,保持比例,并如实回报「原请求 → 实际请求」。

### 3.5 提示词规则

- 第 13 条:**刷色 / 换材质分两条路**。色相明度小幅挪动(黑壳→海军蓝)用 `paint`;白色件→黑色、亮面→哑光、塑料→金属这类"材质本身变了"必须 `edit_image` —— 逐像素等比缩放会把亮面和暗面一起压扁,看起来就是盖了一层色。判据:源区域平均亮度 / 目标亮度 ≥ 2 倍就走模型。同一行还写死了验收判据:**和原图并排能看出改动边界/一圈亮边 → 不合格,不许当成品交付**。
- 第 14 条:模型改局部必须带 `protect`(`region` / `maskAssetId` / `auto:true` 三选一),默认基线=版本链根;报告「保真可疑」不得当成品交付。
- 第 15 条:交付前用 `compare_image` 对账,区域外 >2% 不合格;汇报要说清"改了什么、没改什么、基线是谁"。
- 第 16 条:同一处最多核对两轮,不许用反复裁剪/对比代替结论。

## 5. 局限与边界(必须说清)

1. **paint 需要选区。** 颜色/区域/蒙版三者至少给一个。像你这张"白壳+白键帽"的实拍图,键帽与外壳同色,颜色选择分不开,需要键帽蒙版或逐区处理;而你描述的"黑壳+白键帽"正是颜色选择最擅长的场景。
2. **护栏只保护"区域外"。** 区域内仍是模型画的,布局是否被重排由锚定率提示,不能保证。只是挪色相请用 paint;材质变了就必须接受"区域交给模型"。
7. **auto 护栏按连通块放行。** 它不会分辨"这块里哪个是徽标":要改的物体和被保护的徽标/屏幕连成一片时,auto 保护不到,必须改用 `region`/`maskAssetId`。auto 模式报告的"区域外 0%"是构造出来的,看 `kept`(留了几片)和 `revertedShare`(还原了多少)才有意义。
8. **材质换色要花模型钱。** 约 ¥0.35/张、40–60s;且模型对细节有漂移风险(本次锚定 0.80,键位/徽标/屏幕未动,但不是每次都能这样)。
3. **锚定率不是判决书。** 文字替换会新增边界(锚定下降是正常的);密集重复结构平移后仍可能找到相似边界(锚定不降太多)。它配合"区域外改动"和热图看。
4. **羽化只在允许区域内。** 矩形外强制 0,不会因为羽化把模型像素漏到区域外;代价是区域内边缘 1-3px 过渡。
5. **端点约束是实测出来的。** 不同中转/模型可能不同;本地 clamp 采用更保守的通用值(16 倍数、≥1MP、≤3840)。
6. **自动键帽蒙版不完美。** 实拍测试里用亮度分块做的键帽蒙版漏掉了少数与外壳亮桥相连的键(换色后仍留白)。这是"自动选区"的普遍问题,不是 paint 的几何保真问题;正式用时应让用户涂蒙版或按颜色选。

## 6. 复现

npm run verify:fidelity          # 纯函数,不联网、不花钱
