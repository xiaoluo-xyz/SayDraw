# 本地合成(像素级合成)—— 可行性分析

> 结论先说:**可行,而且 P0 不需要引入任何新依赖**。
> 这里说的「本地合成」= 在应用内用像素运算完成 **贴图 / 换色 / 形状 / 裁剪 / 拼接 / 文字**,
> 完全不调用生图模型:成本 ¥0、可重复、像素级一致、原始素材不动。

---

## 1. 为什么现在会卡住(需求还原)

会话里的真实任务是:把用户自己的键帽截图贴回生成图的键帽位置、整图调暗 15%、保留键帽圆角、
右侧小屏与 `SayDevice` 文字必须是原件的像素。模型给的三个选项(用户自己 PS / 重绘一次 / 凑合收下)
本质都是"应用没有这个能力"的转嫁。

根因只有两处,都不在模型侧:

1. **工具层没有合成算子**。现有的 `process_image` 只做了 `nativeImage` 的转码/缩放,
   没有任何"把 A 的一小块贴到 B 的某个位置""只把蒙版区域改成浅灰"的能力。
2. **提示词没有路由规则**。systemPrompt 没说"像素级/保持原件不动的活该走本地合成",
   模型只能在"重绘"和"让你自己贴"之间二选一,于是如实回答"本地合成我这边做不了"。

---

## 2. 现有家底(决定这件事的性价比)

| 已有能力 | 位置 | 对本功能的意义 |
|---|---|---|
| `nativeImage` 解码 png/jpeg、`crop`、`resize`、`toPNG/toJPEG` | `src/main/agent/tools.ts` `process_image` | 编解码与裁剪现成 |
| **`toBitmap()` / `createFromBitmap()`** | Electron API | 拿到原始像素进出,这是合成的地基;**不需要 sharp/原生依赖** |
| 渲染进程 canvas 2D(二值蒙版/羽化/彩色标注/扩画布/居中裁剪/水印文字) | `src/renderer/src/lib/mask.ts`、`ExportPanel.tsx` | 文字光栅化与交互式预览的宿主 |
| 资产系统 `saveBufferAsset(kind/parentId/prompt)` + 版本树 + 成本可见 | `src/main/store/assets.ts` | 合成产物天然就是"一个新版本",和现有版本树/对比/导出全打通 |
| 蒙版是一等资产,`edit_image` 已用 `maskAssetId` | `tools.ts` | **本地换色可以直接吃用户涂的那张蒙版**,交互零新增 |
| 导出链(renderer canvas → dataURL → IPC 落盘) | `ExportPanel` + `ASSETS_EXPORT_SET` | 合成结果的落盘/多比例复用同一条链 |

缺口:算子、工具入口、提示词路由、产物 meta(ops / ¥0)与"这是本地合成、没重绘"的诚实标注。

---

## 3. 技术方案

### 3.1 一套纯函数内核 `src/shared/composite.ts`

输入输出都是 RGBA Buffer + 宽高,不依赖 electron,可用 2×2 / 4×4 小图做单测:

- `crop` / `fit` / `pad`(定尺寸画布、扩边、填充底色)
- `paste(src, srcRect → dstRect, opacity, blend)`:`normal / multiply / screen`
- `recolor`(保持明度的换色、亮度/对比/饱和、色温、只作用蒙版区域)
- `shape`(圆角、描边、投影、底色)
- `grid`(N 图拼网格:间距/边距/序号)
- 每次返回 `{ buffer, width, height, log[] }`,`log` 直接进 `ImageMeta.ops` 和「导出参数」

### 3.2 两个执行宿主(同一份内核)

- **主进程(agent 路径)**:`nativeImage.createFromBuffer → toBitmap() → 内核 → createFromBitmap → toPNG/toJPEG → saveBufferAsset`。
  同步、无 IPC 桥、进程内完成,和 `process_image` 同一层。
- **渲染进程(文字 / 交互路径)**:canvas 2D 天然处理 alpha、抗锯齿与字体,`ExportPanel` 已有同款链路。

判据:纯像素算子走主进程;需要字体光栅化(文字/水印/角标)或用户拖动图层走渲染进程。

> ⚠️ 已知坑:Skia 位图是**预乘 alpha**。读入要反预乘、写出再预乘,否则半透明边缘会发黑。
> 实施第一步先做 2 像素对拍(纯红 50% 透明应读回 `255,0,0,128`),不通过就把宿主切到渲染进程 —— 内核不用改。

### 3.3 Agent 工具 `composite_image`

```
composite_image {
  assetId: "asset-xxx",              // 底图
  ops: [ {op:"paste", from:"asset-yyy", srcRect:[x,y,w,h]|"auto", dstRect:[...], opacity:1, blend:"normal"},
         {op:"recolor", mask:"asset-zzz"|null, hue:+12, lightness:-15, preserveLuma:true},
         {op:"shape", corner:26, stroke:2, strokeColor:"#2a2a2a"},
         {op:"crop", rect:[...]}, {op:"pad", rect:[...]}, {op:"grid", ...} ],
  label: "贴回原键帽并整体调暗"
}
```

- 坐标一律**归一化 0–1**,内核换算成像素并把实际绝对值回报给模型(便于下一轮修正);
- 无生图调用 → **¥0**,不受 `gateCheck` 的出图闸门约束(只要求目标资产存在);
- `meta = { ops, sourceAssets, cost: 0 }`,版本树显示「本地合成」,参数面板可复制成配方。

### 3.4 解决"模型量不准像素"(最关键的一步)

这是 agent 驱动合成唯一的真风险,三件套解决,不需要人工:

1. **带坐标网格的参考图**:进入合成任务时,给模型一张叠了 10×10 网格与像素刻度的缩略图
   (和蒙版那张"彩色编号标注图"是同一个思路);
2. **归一化坐标**进、**绝对像素**出(内核回报 `dstRect` 的实际值);
3. **结果图回传自检**:模型看一眼贴得对不对,不对就再合成一次 —— ¥0,可以无限重试。

### 3.5 UI

- 版本树/画布标注「本地合成 · ¥0」,不显示模型名;
- 参数面板展示 ops(可复制为配方、可作为"同参再生成"的反向操作:合成不重跑 API);
- P1:查看器里加「合成」模式(把另一张图当图层拖动/缩放/调透明度)。

## 4. 能力矩阵

| 能力 | 可行性 | 依赖 | 工作量 |
|---|---|---|---|
| 贴图合成(裁剪 → 缩放 → 混合,含透明度/圆角裁切) | 高 | 内核 + nativeImage | 0.3 d |
| 局部/整体换色、明暗冷暖(吃现有蒙版) | 高 | 内核 + mask 资产 | 0.2 d |
| 圆角 / 描边 / 投影 / 底色 | 高 | 内核(手工抗锯齿) | 0.2 d |
| 裁剪 / 定尺寸 / 扩画布 | 现成 | `nativeImage.crop` | 0.05 d |
| 拼接排版(九宫格 / 长图 / 带序号) | 高 | 内核 | 0.2 d |
| 文字 / 水印 / 角标 | 中 | **渲染进程** canvas(主进程没有字体光栅化) | 0.3 d |
| 交互式合成编辑器(拖放图层) | 中 | Konva + 现有导出链 | 1.5 d |

**P0 ≈ 1 天**(内核 + 工具 + 路由规则 + 版本展示 + 真图验收),**P1 ≈ +1.5 天**(文字宿主、拼接、交互式)。

## 5. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| Skia 预乘 alpha | 半透明边缘发黑 | 2 像素对拍 → 反预乘;不行切渲染进程宿主(内核不动) |
| 模型给不准坐标 | 贴歪 | 网格参考图 + 归一化 + 结果自检(¥0 迭代) |
| `nativeImage` 解码格式有限(webp/avif) | 少数素材进不来 | 先用 `process_image` 转 png,或提示用户 |
| 大图内存/耗时(4096² ×4B ≈ 64MB) | 卡顿 | >4096 先等比缩,单次合成实测耗时并记录 |
| 质量预期错位(以为"合成=融合光照") | 用户失望 | 如实标注"本地合成,未重绘";需要光影融合时再走一次 `edit_image`,两条腿 |
| 产物堆积 | 版本树噪音 | `parentId` 挂树,和现有版本树一致 |

## 6. 落地顺序与验收

**P0**
1. `src/shared/composite.ts` 内核 + 单测(纯函数,2×2/4×4 小图断言)
2. 主进程适配器 + `composite_image` 工具 + `meta.ops` / 配方
3. systemPrompt 路由规则:保持原件不变 / 像素级一致 / 换颜色 / 贴 logo / 加文字 / 拼接 → 本地合成;
   需要重新绘制内容 / 改构图 / 换风格 → `edit_image`
4. 真图验收:用键盘这组素材复现「贴回原键帽 + 整体调暗 + 保留圆角」,像素级对齐、¥0、可重复

**验收标准**:截图里那个问题由 agent 自己用 `composite_image` 解决,不再出现"本地合成我这边做不了"。

## 7. 顺带的竞争力

Cherry Studio 的 `painting` 表没有图层/合成概念,只能靠模型重绘;
对"垂直图像工作室"这一定位,本地合成是真正的护城河 —— **¥0 的精确修改**,以及可回改的合成配方。

## 8. 实施记录(P0 已完成 · 2026-10-20)

**内核** `src/shared/composite.ts`(纯函数,不依赖 electron / DOM,直通 alpha 的 RGBA):
`crop` / `scale` / `fitInside` / `expandCanvas` / `pasteImage`(normal·multiply·screen + 透明度)/
`recolor`(色相·饱和·明度·对比·色温,可按蒙版只改局部;`preserveLuma` 只抵消换色带来的亮度漂移,不抵消显式明暗调整)/
`roundCorners`(1px 抗锯齿 + 描边 + 底色)/ `drawGrid`(10×10 坐标网格)/ `gridImages`(拼接)/ `alphaBBox`(自动取主体)。

**像素进出** `src/main/imageops.ts`:实测 Electron `toBitmap()/createFromBitmap()` 都是**预乘 BGRA**
(纯红 50% 透明读回 `[0,0,128,128]`,见 `_demo/premul-probe.cjs`),统一反预乘 → 计算 → 再预乘;
jpeg 若含透明先压白底;>4000 万像素先等比缩。

**工具**(`src/main/agent/tools.ts`):
- `composite_image`:crop / paste(`from` 省略 = 自动取不透明主体)/ recolor(可传蒙版,沿用应用约定「透明=待改」)/
  corners(radius 按短边比例)/ canvas / collage;执行顺序 拼接→裁剪→贴图→调色→圆角→画布;
  坐标全部 0-1 归一化,结果回报**实际像素矩形**,便于模型下一轮修正。
- `inspect_grid`:生成带网格的标注图(`kind: 'annotation'`,不进版本树),让模型数格子量位置。

**产物语义**:`meta = { local: true, ops, sourceAssetIds, cost: 0 }`;版本树/画布显示「本地合成 · ¥0 · 未调用生图模型」,
隐藏「同参再生成」,不显示模型名。

**路由**:systemPrompt 第 9 条 —— 像素级/保持原件的活一律 `composite_image`,**禁止再说"本地合成做不了"或让用户去 PS**;
素材区新增「按需读取,不要整目录灌进来」。

**验证**

| 套件 | 结果 |
|---|---|
| `npm run verify:composite`(内核单测) | 39/39 |
| `npm run verify:composite:live`(真图 + 真工具,Electron 内) | 21/21,512² 全链路 42–61ms |
| 应用内真实 agent(deepseek-flash) | 自动 `inspect_grid` → `composite_image`:贴图 341×341 @ (642,41)、明度 −8%、圆角 20px、1024×1024、**¥0** |

**已知限制(P1)**:文字/水印需要字体光栅化,只能在渲染进程做;本地合成不重绘光影,需要融合时再走一次 `edit_image`;
webp/avif 能否解码取决于 nativeImage。
